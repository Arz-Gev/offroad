# Добавить машину

Машина в игре — это **данные**, а не код. Физика, привод, шины и вид у всех машин общие. Различаются только числа и флаги. Рецепт ниже проводит по всем местам, где у машины есть свои данные, и по тестам, которые говорят, готова ли она.

Что уже умеет общий код (выбирается данными машины):
- привод: постоянный полный, подключаемый полный, задний, передний (`drive.layout`); центральный дифференциал открытый с блокировкой или с вискомуфтой, своя пропорция; на осях открытые дифференциалы с блокировками или самоблоки;
- подвеска по каждой оси: неразрезной мост или независимая (двойные рычаги или стойка Макферсон); любое число осей; поворотные оси любые;
- вид: рисованный кузов Дефендера или скачанная модель; свои колёса модели или наши; мост рисуем всегда мы; независимая подвеска из деталей модели или нарисованная нами; фары по ролям; люстра на крыше; руль и рычаги в салоне из деталей модели; башня.

## Главное правило: никакого кода под одну машину

- В общем коде (`src/`, кроме данных машины) нельзя писать `if (car === 'x')`, `getCar() === ...` или `P.car === ...`. Нельзя использовать `nA === 2` как замену для «это Дефендер».
- Если машине нужно поведение, которого ещё нет (свой тип дифференциала, подвески, коробки), добавь **поле в данных** с умолчанием, при котором остальные машины не меняются. Примеры, как это уже сделано: `drive.layout`, `drive.centreSplit`, `drive.centre: 'viscous'`, `drive.lockers`, `axles[i].type`, `axles[i].linkage`, `axles[i].diff: 'lsd'`, `manualOnly`, `look.lightBar`, `look.cockpit`, `look.turret`.
- Это нужно доказать. Сравни выводы `npm run simtest` до изменения и после: у других машин числа должны совпасть до последнего знака. Если не совпали, умолчание выбрано неверно.
- Новое поле опиши в DEVNOTES.md (раздел про привод, подвеску или шины) .

## Где живут данные машины

| Что | Где |
|---|---|
| Всё о машине: физика (`physics`), вид (`look`), пороги тестов (`tests`) | `src/cars/<id>.js`, формат в `src/cars/README.md` |
| Список машин и порядок в меню | `src/cars/index.js` (один import, одна строка) |
| Мотор: кривая момента, обороты, инерция | `src/vehicle/engines.js`, `ENGINES.<preset>` (каталог: один мотор может стоять на нескольких машинах) |
| Модель | `public/models/<id>.glb`; конфиг подготовки и команды в `assets-src/<id>/README.md`. Сборщик вида — `src/vehicle/model/index.js` (детали — соседние файлы) |
| Титры | `README.md`, раздел с моделями |
| Заметки и числа | `DEVNOTES.md`, раздел «Imported cars» |

Дефендер — такая же машина, как все: `src/cars/defender.js`. Всё, что машина не задала, берётся из общих умолчаний `src/vehicle/defaults.js` (каркас шины, податливость руля, стартер, сцепление, гидротрансформатор, форма амортизатора). Это умолчания обычных деталей, а не чужой машины: всё, что у реальной машины своё, задавай в её файле.

## 1. Реальные данные

Ищи в интернете: страницы производителя, пресс-релизы, тесты журналов, Википедия, carfolio и cars-data. Каждое число подпиши комментарием с источником или пометкой «оценка». Если реальной машины нет (фантазийная), так и напиши.

- **Массы.** `bodyMass` — подрессоренная масса, то есть снаряжённая минус неподрессоренная. `axleMass` — неподрессоренная масса оси: мост или рычаги, колёса, тормоза. Неразрезной мост внедорожника весит 150–210 кг, легковая независимая ось 80–90 кг.
- **ЦМ.** `com: [0, высота, z]`. z = −(доля на передней оси − 0,5) × база: минус — ближе к передней оси. Высота ЦМ по аналогии с соседями: внедорожник 0,85–0,9 м, хэтчбек около 0,5 м.
- **Инерция** `[тангаж, рыскание, крен]`. Оценка: m·(L²+H²)/12, m·(L²+W²)/12, m·(W²+H²)/12 по габаритам кузова, потом сверить по массе и размерам с другими машинами в `src/cars/`.
- **Шины.** `tire.size` и `widthIn` — номинальные дюймы из размера (например 265/70 R17 ≈ 31,6 × 10,4). `rimRadius` — радиус диска в метрах. `pressure` в psi. `grip` больше 1 только для спортивной резины.
- **Мотор.** Новая запись в `ENGINES` в `src/vehicle/engines.js` с кривой `gross([[об/мин, Нм], ...])` по опубликованной кривой или по пиковым точкам. Нужны `idleRpm`, `limiterRpm`, `redlineRpm`, `shiftRpm`, `inertia`, а в `note` — откуда числа. Варианты моторов для панели тюнинга перечисли в `engine.choices` (у легковых и внедорожников обычно `ROAD_ENGINES`).
- **Коробка.** `manual` и `auto` (`ratios`, `reverse`), `finalDrive`, раздатка `transfer` (`high`, `low`). Нет понижающей у реальной машины — не пиши `low`: тогда у машины нет ни клавиши, ни кнопки, ни строки HI/LO, ни ползунка понижающей. Маленькому мотору с автоматом может понадобиться `auto.stallK` выше, иначе мотор глохнет в D на холостых (Lancia 165).
- **Привод** (`drive`):
  - `layout`: `'awd'` (постоянный полный, по умолчанию), `'parttime'` (подключаемый без центрального дифференциала: Jimny, Hilux, Wrangler), `'rwd'` (задний), `'fwd'` (передний).
  - `centreSplit` — доля момента на переднюю группу осей (G 500: 0,4; Integrale: 0,47).
  - `centre: 'viscous'` и `viscous` (Нм на 1 об/мин разницы карданов) для вискомуфты.
  - `lockers: false`, если ручных блокировок нет.
  - `rwd: []`, если у полноприводной машины нет режима 2WD (у большинства постоянных полноприводных его нет: G-Класс, Lancia, БТР; 2WD у Дефендера — игровая добавка).
  - Кнопки управления не пишутся в файле машины: игра сама выводит их из устройства машины (`src/vehicle/controls.js`). Нет понижающей, блокируемого центра, блокировок мостов, 2WD, дополнительных фар или башни — нет и соответствующих клавиш, кнопок на сенсорном экране, пунктов меню и строк на странице управления. Ничего не добавляй машине «как у Дефендера», только то, что есть у настоящей машины.
  - Дифференциал оси: `axles[i].diff: 'lsd'` с `diffLock`. Torsen с распределением до 70 : 30 даёт 0,4.
- **Руль.** `steer.maxAngle` из радиуса разворота, `ratio` — передаточное число рейки, `kingpinTrack`.
- **Тормоза** — моменты на оси, по аналогии с соседями по массе.

## 2. Подвеска

Тип каждой оси, как у реальной машины: `type: 'beam'` (неразрезной мост) или `type: 'independent'` с `linkage: 'wishbones'` (двойные рычаги) или `'strut'` (Макферсон) и кинематикой `rcHeight` (высота центра крена, м; двойные рычаги 0,05–0,15, стойка 0,05–0,10) и `camberGain` (рад развала на метр хода; −0,2…−0,6). У независимой оси `k` — жёсткость у колеса, `springTrack` не нужен. Жёсткость крена у независимой оси от пружин больше (колея шире), поэтому стабилизаторы подбирай заново по `suspcheck`. Тест, что тип работает: `npm run simtest suspension`.

- **Ход** `travel` (м) — полный ход пружины от отбоя до жёсткого упора. Отбойник начинает работать за 5 см до упора.
- **Пружины** `k`. Целься в статическую просадку около 35–45 % хода и 9–10 см до отбойника. Проверяй через `node tools/suspcheck.mjs <id>`.
  - Исключение — низкие машины. Отбойник держит днище над землёй, и запас хода до него может привести к ударам днищем. Lancia оставлена на 51 %, потому что при более жёстких пружинах днище било о гребни на 70+. Решай по `traillap` (шаг 5), а не по проценту.
- **Высота посадки** считается сама: `droopY` подбирается так, чтобы земля в статике была на y = 0. `raise` поднимает кузов и вид вместе (дорожный просвет). Хода он не добавляет.
- **Амортизаторы** `bump` и `rebound`: масштабируй от соседей пропорционально √(k·m).
- **Стабилизаторы** `arb`: доля жёсткости крена спереди чуть больше доли веса спереди. Тогда лёгкая недостаточная поворачиваемость (`suspcheck` печатает обе доли). Стабилизатором заднюю ось против недоворота не лечить: DEVNOTES, «Don't fix understeer with rear roll stiffness».

## 3. Модель

1. **Выбор.** Колёса отдельными объектами или отделимы, до ~400 тыс. полигонов (больше — придётся упрощать, шаг 6), PBR-текстуры, есть салон, открытая лицензия (CC BY нужно указать в титрах). Не годятся экспорты из SketchUp со слитыми деталями, модели без текстур и рипы из игр. Отказы записывай в DEVNOTES, чтобы их не скачивали снова (так записан Land Cruiser J200).
2. **Скачивание** через Sketchfab API: `GET https://api.sketchfab.com/v3/models/<uid>/download` возвращает подписанную ссылку на GLB. В облачной сессии ключ подставляет прокси. Локально ключ лежит в `~/keys/sketchfab_api_key` и передаётся заголовком `Authorization: Token <key>`. Скачанный исходник держи во временной папке вне репо (scratchpad): в репо его не коммить, его всегда можно скачать заново по ссылке.
3. **Осмотр:** `npx @gltf-transform/cli inspect car.glb`. Проверь единицы (габариты должны быть в метрах), направление (перед там, где фары), материалы и примитивы LINES.
4. **Подготовка:** `node tools/prepcar.mjs in.glb out.glb '{json}'`. Зависимости ставь в отдельную временную папку, они перечислены в шапке инструмента. Инструмент запекает систему координат, отделяет колёса (`wheel_*`, `hub_*`, при `tireMaterial` ещё `tire_*`) и печатает контур кузова через каждые 10 см. Из этого контура строятся коллизионные боксы. Проверь, что все группы колёс на месте.
5. **Подвижные детали салона и фары.** Если руль, рычаг коробки или стёкла фар слиты с салоном, вырежи их в отдельные узлы: `node tools/cutparts.mjs` (сначала `LIST='[x,y,z,r]'` показывает куски около точки, потом рамка для каждой детали). Руль: кусок 0,3–0,4 м перед глазами водителя, колонку не трогай. Проверь в `tools/rigview.html?car=<id>`, что руль целый и при повороте направо крутится по часовой стрелке.
6. **Сжатие.** Модель до 400 тыс. полигонов не сжимай: в `public/models/` идёт то, что вышло из prepcar и cutparts. Только если полигонов больше, сжимай как в `assets-src/btr80/README.md`: optimize с `--join false --flatten false` (иначе колёса сольются обратно с кузовом). Базовые текстуры в WebP с потерями, normal map в WebP без потерь: с потерями затенение идёт пятнами.
7. **README** в `assets-src/<id>/`: ссылка на источник, автор, лицензия, масштаб, аргументы, с которыми запускал prepcar и cutparts, и команды. Это единственный файл в этой папке: ни моделей, ни картинок.
8. **Арки.** `archTop` в физике: открой `tools/rigview.html?car=<id>` и вызови `measureArches()` в консоли.

## 4. Регистрация

- Файл `src/cars/<id>.js` (скопируй ближайшую по типу машину), поля описаны в `src/cars/README.md`:
  - `physics`: `name`, `engine: { preset, choices }`, `bodyMass`, `bodyInertia`, `com`, `aero.cdA`, `wheelbase`, `track`, `axles` (у каждой оси `type`), `tire`, `steer`, `brakes`, `manual`, `auto`, `transfer`, `finalDrive`, `drive`, `load`.
  - `colliders`: `[имя, [cx, cy, cz, hx, hy, hz, скругление]]` по контуру из prepcar, в системе кузова при статике (земля y = 0, середина базы z = 0, −z вперёд).
  - `tests.t100`: полоса вокруг реального разгона 0–100. Для тяжёлых машин нужен свой сценарий, как `btr` в simtest.
- `look` (поля в `src/cars/README.md`):
  - `url`, `author`, `credit`.
  - `wheel: { R, width }` — своя шина модели по замеру prepcar (`rim`, `hubSpins` при необходимости).
  - `eye` — глаза водителя, учитывай сторону руля; `hoodEye`; `chase: { dist, target }` для машин сильно меньше или больше Дефендера.
  - `lamps: { head, bar, rear, lenses }`: позиции лучей и стёкла фар по ролям (имена материалов или вырезанных узлов).
  - `cockpit: { steeringWheel, gearLever }` — узлы, вырезанные в шаге 3.5.
  - `lightBar`, только если на настоящей машине (или на её модели) есть люстра на крыше, тогда луч `bar` идёт от неё; не ставь её «как у Дефендера». Без `lightBar` и без `lamps.bar` у машины просто нет дальнего луча люстры, клавиша J отвечает, что люстры нет, а переключатель в меню скрыт; `suspension`, если у модели свои рычаги; `turret`, если есть башня.
- Строка в `src/cars/index.js`.
- `ENGINES.<preset>` в `src/vehicle/engines.js`, если мотора ещё нет в каталоге.
- Титры в `README.md`.

## 5. Проверки (все обязательны, числа в отчёт)

Во всех инструментах с `CAR=` машина берётся в стоковой настройке.

| Команда | Готово, когда |
|---|---|
| `npm run simtest` | 0 FAIL. У других машин числа совпадают с прогоном до изменений (сравни выводы через diff). |
| `npm run simtest cars` | ошибка высоты посадки меньше 1,5 см, 0–100 в полосе `tests.t100` |
| `node tools/suspcheck.mjs <id>` | просадка и запас хода как в шаге 2, доля крена спереди чуть больше доли веса |
| `node tools/difftest.mjs <id>` | `split` равен `centreSplit` ±2 %. С TC машина трогается, когда одна ось на льду. |
| `CAR=<id> node tools/traillap.mjs 60`, `70`, `85` | `rollovers 0`; `near bump stop` около 1,5 % или меньше; нет строк `spike ... body contacts` (это удар кузовом о землю) |
| `CAR=<id> node tools/handling.mjs` | нет опрокидываний и отрыва колёс в круге; боковое ускорение правдоподобно для машины |
| `CAR=<id> node tools/yawtest.mjs` | после сброса газа на 90 км/ч угол заноса (`beta`) не растёт |
| `npx vite build` | собирается |
| `tools/rigview.html?car=<id>` | подвеска снизу на сжатии и отбое, руль, колёса без проваливания в кузов |
| игра в браузере | нет ошибок в консоли; скриншоты сбоку, 3/4, из кабины днём и ночью, снизу, с фарами ночью, на трейле. Скриншоты отправь пользователю, в репо их не клади. |

Браузер без ручного меню: перед загрузкой страницы запиши в `localStorage` ключ `offroad.settings.v1` = `{"car":"<id>"}` и `offroad.introSeen.v1` = `1`. Chromium лежит в `/opt/pw-browsers/chromium`. Физику (боксы, ход подвески, пятна шин) показывает Tab → Show physics.

## Известные ограничения (не удивляйся)

- Мост и нарисованная независимая подвеска — наши общие детали, а не детали модели: они повторяют размеры машины (колея, ход, высота), но не её конкретные рычаги. Свои рычаги модели пока умеет только двойная подвеска на рычагах (`look.suspension`, как у БТР).
- Салоны скачанных моделей тёмные.
- Радиус шины считается из дюймов: `0.42 × дюймы / 33`.
